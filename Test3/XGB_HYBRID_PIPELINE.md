# XGBoost Hybrid Pipeline (Concise, Core Mechanisms)

This document focuses only on the **core mechanics** of the hybrid
XGBoost pipeline: what features are used, how router signals are
extracted, and how train/test submission is produced.

## 1) What XGBoost actually sees

The XGBoost regressors take **all K=8 wide features** from
`train_features_k8.csv` plus **router signals** extracted from the
Transformer.

### 1.1 Base K=8 wide features

Generated by `feature_engineering_k5.py` (K=8). Each row is a
`game_episode` with last 8 events expanded wide.

Key groups:

- Per-event features for all 8 steps (`t=0..7`):
  - `start_x_t`, `start_y_t`, `dt_t`, `ep_idx_norm_t`
  - `x_zone_t`, `lane_t`, `dist_to_goal_t`, `angle_to_goal_t`
  - `type_id_t`, `res_id_t`, `is_home_t`

- Masked features for first 7 steps (`t=0..6`):
  - `end_x_t`, `end_y_t`, `dx_t`, `dy_t`, `dist_t`, `speed_t`

- Episode-level:
  - `last_result_encoded`

These are the same features used by `train_unified_model.py`.

### 1.2 Router signals (added on top)

Extracted from the trained `FiLMSpatialMoETransformer`:

- `router_gate` (scalar, 0~1)
- `router_zone_logit_0..3` (raw logits for 4 zones)

These are **the only additions** to the base K=8 features.

## 2) How router signals are extracted

Script: `scripts/extract_router_features.py`

Input:
- `open_track1/train_features_v2.csv` (sequence format for Transformer)
- `open_track1/film_smoe_transformer.pt`

Steps:
1) Build sequences with `prepare_sequence_data` (K=8)
2) Apply checkpoint scalers (`scaler_mean/scale`)
3) Run Transformer with `temperature=0.05`
4) Save `router_gate` and `aux_zone` logits to
   `open_track1/xgb_hybrid_features.csv`

Test-time equivalent:
- `scripts/extract_router_features_test.py`
- Output: `open_track1/xgb_hybrid_features_test.csv`

## 3) Merge logic (train)

Script: `scripts/train_xgb_regressor.py`

```
df = train_features_k8.csv
  ⨝ (game_episode)
     xgb_hybrid_features.csv
```

- The merge key is `game_episode`.
- `game_episode` is **not** used as a model feature.

## 4) XGBoost training

Two regressors are trained independently:

- `XGBRegressor` → `target_end_x`
- `XGBRegressor` → `target_end_y`

Training uses:
- 5-fold KFold OOF evaluation
- Objective: `reg:absoluteerror` (L1)
- Hist tree + CUDA

Full models are saved to:
- `models/xgb_full_x.json`
- `models/xgb_full_y.json`

Feature list is saved to:
- `models/feature_columns.txt`

## 5) Test-time submission

Script: `scripts/predict_xgb_submission.py`

Inputs:
- `open_track1/test_features_k8.csv`
- `open_track1/xgb_hybrid_features_test.csv`
- Saved models in `models/`

Process:
1) Merge test K=8 features + router signals on `game_episode`
2) Predict `end_x`, `end_y`
3) Clip to field bounds `[0,105]` and `[0,68]`
4) Save `open_track1/submission_xgb_hybrid.csv`

## 6) Why this works

- Router outputs provide **explicit spatial topology** (4-zone logits).
- XGBoost uses these logits at shallow depth to split boundary vs in-field.
- Trees handle sharp boundary decisions better than smooth regressors.
