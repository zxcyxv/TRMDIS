# XGBoost Regression Input Features

This document describes exactly which features are fed into the XGBoost
regression models in `scripts/train_xgb_regressor.py`, and how those features
are produced.

## 1) Data sources and merge logic

The XGBoost feature matrix `X` is constructed by merging two CSV files on
`game_episode`:

1) **Base K=8 wide features**
   - File: `open_track1/train_features_k8.csv`
   - Generated by: `feature_engineering_k5.py`
   - Structure: one row per `game_episode`, with last `K=8` events
     expanded into wide columns.

2) **Router-derived features**
   - File: `open_track1/xgb_hybrid_features.csv`
   - Generated by: `scripts/extract_router_features.py`
   - Structure: per-episode router outputs extracted from the
     `FiLMSpatialMoETransformer` (`train_film_smoe2.py`).

Merge logic in `scripts/train_xgb_regressor.py`:
- `df = df_k8.merge(df_gate, on="game_episode", how="left")`
- A hard check enforces that `router_gate` has no missing values.

## 2) Columns excluded from X

After merging, the code excludes only:
- `game_episode`
- `target_end_x`
- `target_end_y`
- `last_result_name`

All remaining columns become model inputs.

## 3) Base K=8 wide features (from train_features_k8.csv)

The base feature block is created in `feature_engineering_k5.py`
via `create_wide_features()` and `get_feature_columns()`. It is composed of:

### 3.1 Per-event features for the last 8 events (K=8)

Each feature appears for every position `t = 0..7`:

- `start_x_t`
- `start_y_t`
- `dt_t`
- `ep_idx_norm_t`
- `x_zone_t`
- `lane_t`
- `dist_to_goal_t`
- `angle_to_goal_t`
- `type_id_t`
- `res_id_t`
- `is_home_t`

These are the **full event features** for each of the last 8 actions.

### 3.2 Masked features for the first 7 events (K-1 = 7)

These features exist only for `t = 0..6`:

- `end_x_t`
- `end_y_t`
- `dx_t`
- `dy_t`
- `dist_t`
- `speed_t`

These are excluded for the last event (t=7) to avoid leakage.

### 3.3 Episode-level feature

- `last_result_encoded`

This encodes the result type of the last event.

## 4) Router-derived features (from xgb_hybrid_features.csv)

These are added to the K=8 wide features and are **the only difference**
from the input set used by `train_unified_model.py`.

### 4.1 router_gate

- Column: `router_gate`
- Definition: sigmoid output of the spatial router (probability of boundary expert).
- Range: `[0, 1]` (continuous).
- Source: `FiLMSpatialMoETransformer.forward()` output key `gate`.

### 4.2 4-class zone logits

Four raw logits from the auxiliary zone head:

- `router_zone_logit_0` (In-field)
- `router_zone_logit_1` (Top-out)
- `router_zone_logit_2` (Bottom-out)
- `router_zone_logit_3` (Goal-line)

These are **logits**, not probabilities. They are generated by
the auxiliary head `aux_zone` in `FiLMSpatialMoETransformer`.

## 5) Target columns (not in X)

The regression targets are:
- `target_end_x`
- `target_end_y`

These are excluded from `X` and used as labels.

## 6) Summary: what X actually contains

The XGBoost input features are:

1) **All K=8 wide features** from `train_features_k8.csv`:
   - 11 event features × 8 timesteps = 88 columns
   - 6 masked features × 7 timesteps = 42 columns
   - `last_result_encoded` = 1 column

2) **Router augmentation features**:
   - `router_gate` = 1 column
   - `router_zone_logit_0..3` = 4 columns

Total input feature count:
- 88 + 42 + 1 + 1 + 4 = **136 columns**

Note: the exact total may be higher if `train_features_k8.csv` contains
additional columns beyond those defined in `get_feature_columns()`. The
actual list used is computed dynamically by excluding only the four
columns in Section 2.

## 7) Where each feature originates (traceability)

- `train_features_k8.csv`
  - Created in `feature_engineering_k5.py` at:
    - `create_event_features()`
    - `create_wide_features()`
    - `get_feature_columns()`
- `router_gate` and `router_zone_logit_*`
  - Created in `scripts/extract_router_features.py`
  - Model: `FiLMSpatialMoETransformer` in `train_film_smoe2.py`
  - Inputs: `train_features_v2.csv` sequences scaled with checkpoint scalers
  - Router temperature: `0.05`

## 8) Notes on consistency

- The merge key is `game_episode`. Both CSVs must have it.
- If `router_gate` is missing for any episode, training stops with an error.
- The model does **not** perform feature scaling for XGBoost inputs.
